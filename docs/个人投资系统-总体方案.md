# 个人投资系统 — 基于 Bubbles 的总体方案（决策驱动版）

> **核心理念：决策驱动，而非信息驱动。**
> 系统的主产物是**买入 / 卖出 / 否决决策书**，信息收集只是为决策服务的手段。
> 当决策做不出来时，系统必须明确回答"**还缺什么依据**"，并反向生成定向调研任务——
> 这就是用决策来检验信息是否足够、依据是否充足的机制。
>
> **边界声明：系统只做研究与辅助决策，不接券商、不自动交易。最终拍板权在 Paulus。**

---

## 1. 现状问题与设计转向

### 1.1 旧体系的问题

旧体系（P0–P12 + 9 skills + 定时资讯流）本质是**信息流水线**：

| 问题 | 表现 |
|---|---|
| 信息淹没决策 | 日报/周报产出大量"值得关注"，但没有落到买/卖结论 |
| 研究无假设 | 分析从"全面了解 XX"开始，没有可证伪的预判，调研无法收敛 |
| 依据不闭环 | 决策是否"依据充分"没有检查，靠感觉 |
| 无组合目标 | 不知道买多少算够、赚多少算达标，缺少总量约束 |
| 卖出无规则 | 买入有 P5 流程，卖出信号（P6）缺少和假设挂钩的触发条件 |

### 1.2 设计转向

```
旧：信息 → 分析 → （人自己想办法决策）
新：目标/约束 → 假设 → 定向验证 → 决策书（买/卖/否决）
                         ↑_______________↓
                    依据不足时输出"缺失信息清单"，
                    反向驱动定向调研（信息缺口 → 调研任务）
```

## 2. 目标与约束体系（IPS 数字化）

写成机器可读的 **`investment/policy.yaml`**，由风控脚本（非 LLM）强制校验。**以下数值为占位示例，需 Paulus 填定后生效**：

```yaml
# investment/policy.yaml — 投资政策声明（系统硬约束）
goals:                        # 赚钱目标
  annual_return_target: 0.15  # 年化收益目标 15%（示例）
  profit_target_cny: 200000   # 年度绝对收益目标 ¥200k（示例）
  max_drawdown: 0.15          # 组合最大回撤容忍度 15%
limits:                       # 总量约束
  max_positions: 8            # 最大持仓股票数（含基金/标的上限）
  max_watchlist: 15           # 观察池上限（超过必须淘汰）
  max_total_investment_cny: 1000000  # 最大持仓总金额
  min_cash_ratio: 0.30        # 最低现金比例（核心配置下限）
  max_single_position_pct: 0.20     # 单票 ≤ 总持仓 20%
  max_industry_pct: 0.30      # 单一行业 ≤ 30%
rules:
  min_days_between_same_buy: 30     # 同标的两次建仓间隔 ≥ 30 天
  review_after_buy_days: 30         # 买入后 30 天强制复核假设
  sell_stop_loss_pct: -0.20         # 硬止损线 -20%
```

### 2.1 目标追踪记分卡（月度产出，飞书推送）

| 指标 | 目标 | 当前 | 状态 |
|---|---|---|---|
| 年化收益（滚动） | ≥15% | 实测 | 🟢/🟡/🔴 |
| 年度绝对收益 | ¥200k | 实测 | — |
| 最大回撤 | ≤15% | 实测 | — |
| 持仓数 / 上限 | ≤8 | 5/8 | 剩余坑位 3 |
| 持仓总金额 / 上限 | ≤¥1M | 实测 | — |
| 现金比例 / 下限 | ≥30% | 实测 | — |
| 决策胜率（30 天） | — | 买入建议达成率 | 复盘用 |

**目标的作用不只是看板**：`max_positions` 制造稀缺性——满仓时新买入必须回答"**替换谁**"（挤掉最弱持仓），让组合始终是优胜劣汰的锦标赛；`profit_target` 让月度审计能判断"是否需要提高进攻性/降低仓位"，而不是永远被动持有。

## 3. 标的决策状态机

每个标的在系统中只有一个状态，所有研究围绕**推动状态流转**展开：

```
            ┌──────────────────────────────────────────────┐
            ↓                                              │
 [观察池] ──建立假设──▶ [验证中] ──决策就绪──▶ [待决策] ──人批准──▶ [持仓]
  watchlist   │            │                   │   否决→[否决归档]    │
              │            │                   │                     │
              │        假设被证伪 ──▶ [证伪归档] │              触发卖出条件
              │                          （写明为何排除）             ↓
              └───────────────────────────────────────        [卖出决策]
                                                                │
                                            卖出/减持 → [复盘归档]（P11+P12）
```

- 状态写入 **`investment/portfolio.yaml`**（每标的：状态、假设 ID、目标价、止损、复核日期、决策书链接）。
- **观察池有上限（15）**：进新标的必须淘汰旧的，防止调研发散。
- 每次状态流转必须有一份决策书（§5 模板），无决策书不流转。

## 4. 假设-验证-决策方法论

### 4.1 假设卡（可证伪是硬要求）

新进观察池/新建仓的第一步是写假设卡 `stocks/{标的}/{标的}-假设卡.md`：

```markdown
## 假设 H1（一句话，可证伪）
小米汽车 2026 年交付量翻倍驱动股价 12 个月内到 HK$70（+40%）。

## 关键驱动因子（按敏感度排序）
1. 季度交付量 ≥ 12 万台（跟踪指标，月度可查）
2. 汽车毛利率 ≥ 20%（财报验证）
3. 2026 国补政策不退坡（事件验证）

## 证伪条件（任一触发 → 假设失败 → 归档/卖出）
- 两个季度交付量 < 预期 80%
- 毛利率连续两季下滑
- 竞品价格战使市占率掉 5pct 以上

## 时间窗口与目标价
12 个月 / 目标价 HK$70 / 止损价 HK$42
```

**规则**：没有证伪条件的假设不允许进入验证阶段。这就是"验证"有方向、调研能收敛的前提。

### 4.2 验证 = 定向找证据（不是全面调研）

验证阶段只回答三个问题，产出**证据表**（每条带来源 + 时间戳 + 支持/反对标记）：

1. 驱动因子当前值是多少？（数据）
2. 有哪些证据支持 / 反对每个驱动因子？（多空都找，用 pi-web-access 抓原始研报/公告 PDF）
3. 证伪条件有没有被触发？（硬性检查）

### 4.3 决策就绪度门（依据充分性检验 — 本方案的关键机制）

出决策书前，风控脚本 + 复核会话逐项检查**决策就绪清单**：

| # | 检查项 | 不满足时 |
|---|---|---|
| 1 | 假设卡完整（含证伪条件、时间窗口、目标/止损价） | 打回补假设 |
| 2 | 每个驱动因子有**当期**数据（≤7 天或最近报告期） | 列入缺失信息清单 |
| 3 | 支持与反对证据**都**收集过（空头复核已跑） | 补跑空头复核 |
| 4 | 证伪条件逐条核对，均未触发 | 状态改"证伪归档" |
| 5 | 风控硬规则全 ✓（§7） | 阻断，人可豁免并留痕 |
| 6 | 预验尸已写（这笔会怎样亏钱） | 打回补写 |

**任一项不满足 → 输出《缺失信息清单》**（缺什么数据、去哪找、谁来跑），自动创建为定向调研任务；清单返回给主流程而不是硬凑结论。这样"决策做不出来"本身就是系统最重要的输出之一——它精确回答了"信息是否足够"。

## 5. 决策书（系统的主产物）

### 5.1 买入决策书 `stocks/{标的}/{标的}-买入决策书-YYYY-MM-DD.md`

```markdown
# 买入决策书：XX（代码）
## 决策：买入 / 否决 / 继续观察（三选一，禁止"值得关注"这类无结论表述）
- 建议仓位：__% ｜ 目标价：__ ｜ 止损价：__ ｜ 复核日期：买入后 30 天
- 若持仓已满（≥8 只）：替换标的：__（最弱持仓 + 替换理由）

## 假设（引用假设卡 H1，一句话复述 + 证伪条件）
## 依据充分性（决策就绪清单 6 项逐条 ✓/✗）
## 支持证据（每条：来源链接 + 时间戳 + 对应驱动因子）
## 反对证据（空头复核会话结论，原文附后）
## 预验尸：最可能的亏钱路径
## 组合影响：持仓数 5→6 / 行业集中度 __% / 现金比例 __%（风控脚本输出）
## 页脚：session-id / 模型 / 数据快照索引 / 决策日志 ID
```

### 5.2 卖出决策书（触发即出，不留拖延空间）

**卖出触发条件**（任一命中 → 流水线自动强制生成卖出决策书）：

| 触发 | 动作 |
|---|---|
| 假设证伪条件命中 | 强制清仓建议（除非人豁免并改假设） |
| 达到目标价 | 减持/止盈决策书 |
| 触及止损线 -20% | 强制清仓决策书 + 红信号推送 |
| 驱动因子恶化但未证伪 | 减持决策书 |
| 持仓满员且有更优候选 | 替换决策书（对比表） |
| 30 天复核日到期 | 复核决策书：持有/加/减/卖，必须给结论 |

卖出决策书结构同买入（决策/依据/证据/预验尸/组合影响），外加"**当初买入假设的兑现情况**"一节——这是复盘的钩子。

### 5.3 否决决策书（也要留痕）

否决同样写决策书：否决理由 + "何种条件下重新考虑"。月度审计统计否决标的的后续走势（错杀/躲过），校准研究偏差。

## 6. 决策节奏（人只在关键节点出现）

| 节奏 | 决策会内容 | 产出 |
|---|---|---|
| 每日 | 红信号 → 是否触发卖出条件 | 卖出决策书（如有）/ 无事不动 |
| 每周 | 观察池状态巡检：谁验证中、谁就绪、谁该淘汰 | 待决策书 + 缺失信息清单 |
| 买入/卖出时刻 | 飞书审批卡片拍板 | 决策书定稿 → 决策日志 |
| 每月 | 记分卡 vs 目标 + 再平衡 + 否决复盘 | 月报 + 政策参数修订提案 |

**信息消费原则**：日报/周报只保留两类内容——① 触发状态流转的信号；② 驱动因子数据更新。其余一律进摘要归档不推送，减少信息噪音。

## 7. 风控硬规则（脚本校验 `risk-check.sh`，不交给 LLM）

1. 持仓数 + 1 ≤ `max_positions`（否则必须指定替换标的）
2. 持仓总金额 + 新买入 ≤ `max_total_investment_cny`
3. 单票 ≤ `max_single_position_pct`；单行业 ≤ `max_industry_pct`
4. 买入后现金比例 ≥ `min_cash_ratio`
5. 同标的两次建仓间隔 ≥ 30 天
6. 买入价高于目标价 10% 以上 → 阻断
7. 无当期价格/PE、证据无时间戳 → 阻断出决策书
8. 组合回撤 > `max_drawdown` → 全线停止新开仓，强制降仓审视

任何 ✗ 标红进飞书卡片；人可豁免，豁免理由必进决策日志。

## 8. 自动化流水线改造（决策导向）

| # | 任务 | cron | 决策职责 |
|---|---|---|---|
| 1 | **盘前简报** | `30 7 * * 1-5` | 只报：①持仓驱动因子数据更新 ②隔夜是否触发卖出条件 |
| 2 | **信号扫描** | `0 */1 9-15 * * 1-5` | 红信号 → 立即触发卖出条件检查 → 推决策卡片 |
| 3 | **收盘决策检查** | `30 15 * * 1-5` | 逐持仓核对止损/目标/证伪条件；到期复核日强制出复核决策书 |
| 4 | **周度决策会** | `0 9 * * 6` | 状态机巡检：推进验证中标的 → 出待决策书或《缺失信息清单》；观察池淘汰 |
| 5 | **月度审计** | 月末 | 记分卡 vs `policy.yaml` 目标 + 再平衡 + 否决/买入胜率复盘 + 政策修订提案 |
| 6 | **验证任务**（事件驱动） | 由缺失信息清单创建（一次性 `--at`） | 定向补齐某个驱动因子证据，回写证据表 |

创建示例：

```bash
bubbles create -n "周度决策会" \
  -p "工作目录 investment/。读取 portfolio.yaml 与各标的假设卡：\
1) 对每个'验证中'标的跑决策就绪度门 6 项检查；\
2) 就绪的产出买入决策书（含空头独立复核与 risk-check.sh 结果）；\
3) 不就绪的产出《缺失信息清单》并为每条缺失信息创建定向调研任务；\
4) 观察池超 15 只时按假设强度淘汰；\
5) 结论（决策书链接 + 待拍板清单）发飞书。禁止输出无结论的'值得关注'。" \
  -s "0 9 * * 6"
```

## 9. 人工在环：飞书决策卡片

```
卖出条件命中/周度决策会 → 决策书生成
  → 风控脚本校验（硬规则逐条 ✓/✗）
  → 空头独立复核会话（第二个 bubbles 任务，独立上下文）
  → 飞书【决策卡片】：结论(买/卖/否决) + 假设 + 依据充分性 + 多空结论 + 组合影响
  → Paulus 拍板：批准 / 否决 / /refork 换角度重跑
  → 决策日志落盘 → 下单人工执行 → 30 天强制复核
```

决策日志（`investment/decision-log.md`，追加式）：日期 / 标的 / **决策(买/卖/否决)** / 假设 ID / 依据充分性(6 项结果) / 仓位止损目标 / 替换标的 / 拍板人 / 30-90 天结果回填 / P12 纪律评分。

## 10. 架构（不变的底座）

```
交互层   飞书（决策卡片/记分卡/红信号） · pi TUI · /bubbles · /refork
编排层   bubblesd：6 条决策流水线 + 失败告警
智能体层 pi + 9 skills + pi-web-access（定向取证，抓原始研报/公告 PDF）
决策层   假设卡 → 证据表 → 决策就绪度门 → 决策书 → 决策日志   ★ 本次新增
数据层   futu / mx-* / Tavily / RSS + point-in-time 快照 _snapshots/
知识层   portfolio.yaml · policy.yaml · 决策书库 · SQLite 审计 · COS→Obsidian
```

TradingAgents 最佳实践的落点：多空辩论=空头独立复核会话；风控独立=policy.yaml 脚本校验；组合经理终审=人；point-in-time=快照目录；持久决策日志=decision-log.md。

## 12. 风险与边界

- **不自动交易**：决策书止于"建议 + 审批"，下单人工执行。
- **数字目标的双刃剑**：收益目标可能诱导过度交易，故月度审计里收益目标只作"进攻性调节参考"，硬约束是回撤和仓位上限——**先活下来，再赚钱**。
- **LLM 幻觉**：假设卡证伪条件 + 空头独立复核 + 硬规则脚本 + 快照引用，四道防线；决策书只当研究助理初稿。
- **数据许可与合规**：mx-*/futu/Tavily 遵守各自 API 条款；产出仅供个人决策参考，不构成投资建议。
