# 持仓决策评审（假设-验证-决策）

## 概述

**决策驱动，而非信息驱动**：本流程的主产物是决策书（买入/卖出/保持/加仓/否决），信息收集只为决策服务。当依据不足做不出决策时，输出《缺失信息清单》反向驱动定向调研——这是用决策检验信息是否足够的核心机制。

- 状态机与约束：`investment/policy.yaml`（硬约束）；持仓主数据在 bubblesd SQLite `holdings` 表（`bubbles holding` CLI / 飞书 `/holding` / pi 工具 `bubbles_holding`），`portfolio.yaml` 降为非正式快照
- 决策留痕：`investment/decision-log.md`（含否决，一行一决策）
- 决策书输出：`investment/stocks/{标的}/` ；日报：`investment/holding/daily/`

## 流程（9 步，按序执行，禁止跳步）

### Step 0 · 数据就位检查（含降级）
- 行情：futuapi（港美股，需 OpenD）→ mx-data（A 股）→ **降级：腾讯行情 `qt.gtimg.cn/q=hk01810,sh603662`（免密钥）**
- 新闻/宏观：multi-tavily-search → **降级：东方财富搜索 API（见 references/data-sources.md）**
- 所有通道不可用时停止流程并报告，**禁止凭记忆写金融数据**（CLAUDE.md 约束 1）

### Step 1 · 投资环境分析（四维 + 分级）
政策（会议/货币/产业政策）、经济与市场（流动性/指数趋势）、国际（美联储/中美/地缘）、行业景气（持仓所属行业逐个）。
每条信号：**红/黄/绿分级 + 来源链接 + 发布日期**。产出"环境结论→对组合的含义"（如：鹰派加息→新开仓要挑剔）。

### Step 2 · 持仓监控表
逐标的：现价 / 成本 / 浮盈亏 / PE / **卖出触发条件检查**（止损线、目标价、假设证伪条件、复核日到期）。触发表见 Step 5。

### Step 3 · 假设建立 / 更新（可证伪是硬要求）
每标的一张假设卡：一句话可证伪陈述 + 驱动因子（可跟踪指标）+ **证伪条件** + 时间窗口 + 目标价/止损价。
**无证伪条件的假设不许进入验证**。存量持仓假设失效的（如买入理由不兑现），写明"当初假设兑现情况"。证伪条件的**可触发性由 invest-bear 审核**（防止写得过宽让假设不可证伪）。

### Step 4 · 定向验证（支持 + 反对，双栏）
对每个驱动因子找证据，**支持证据与反对证据（空头视角）都要收集**，每条：结论 + 来源 + 日期。逐驱动因子标 ✓/✗/⚠。
**证据快照硬性要求**：当日行情/财务/引用网页关键段落必须落盘 `{INVEST_ROOT}/_snapshots/YYYY-MM-DD/{ticker}/` 并在 decision-record 的 `snapshot_index` 引用——防复盘后视偏差。
估值对照：**按 stock_type 分类估值带**（policy valuation_bands）——成长 30–80x、价值 8–25x、**周期股禁用 PE 带**（低 PE 陷阱，用 PB/商品价格分位）、纯概念默认否决。对照同主题标的估值差。

### Step 5 · 决策（强制结论，禁止"值得关注"）
决策矩阵：

| 触发条件 | 决策 |
|---|---|
| 浮亏触及止损线（**2×ATR(60日) 与 -20% 取更宽者**，硬底 -35%） | **强制卖出决策书**（豁免须书面理由 + 改假设 + 新止损） |
| 假设证伪条件命中 | 卖出/清仓 |
| 达到目标价 | 减持/止盈决策书 |
| 驱动因子恶化未证伪 | 减持 |
| 假设验证通过 + 估值在分类带内 | 买入/加仓 |
| 假设被证伪（如商品价格反向） | **否决**（写"重新考虑条件"） |
| 依据不足 | 保持现状 + **缺失信息清单**（阻断相应动作） |

**纪律高于判断**：止损触发时先出卖出决策书，再讨论豁免。
**冷却期**：同标的两次决策书间隔 ≥ decision_cooldown_days（默认 7 天），止损/证伪强制触发除外——防过度交易。
**熔断**：组合单日回撤 ≥8% 或大盘单日跌幅 ≥5% → 冻结新开仓 24h，卖出决策需 bear 二审 + 人工拍板（policy circuit_breaker）。

### Step 6 · 决策就绪度门（6 项，逐条 ✓/✗ + **程序化强制**）
①假设卡完整 ②驱动因子当期数据（≤7 天或最近报告期）③多空证据都收集 ④证伪条件未触发 ⑤风控硬规则过 ⑥预验尸已写。
**任一不过 → 输出《缺失信息清单》**（缺什么/去哪找/期限），且阻断对应决策（如缺成本→阻断加仓，放行保持）。
**硬门槛**：决策书写完必须过 `scripts/risk_check.py <决策书.md> --stock-type <类型>`，**退出码 1 = 阻断，不得提交**——就绪度门不再靠自评，risk_check 机械比对 policy.yaml（仓位算术/估值带/bear 反对/沙盒/熔断/止损深度）。

### Step 7 · 组合影响 + 预验尸
- 组合影响：持仓数变化（≤max_positions，满员须指定替换标的）、行业合并敞口（≤30%）、现金比例（≥30%）、**相关簇合计**（同一驱动逻辑如"中国智造+科技"≤50%，防伪分散）
- 预验尸：这笔决策最可能的亏钱路径 + 应对
- **全量持仓评审时每标的独立子流程**（scout+analyst 逐标的跑，最后汇总）——防长上下文后半段质量衰减

### Step 8 · 留痕与推送（四件套，缺一不可）
1. 决策书 → `investment/stocks/{标的}/{标的}-{决策}决策书-YYYY-MM-DD.md`（模板见 references/templates.md，**末尾必附 decision-record**，schema 见 references/decision-record.md）
2. 决策日志 → `decision-log.md` 追加一行（含否决；事后结果列留待月度审计回填）
3. **持仓 DB（主数据）** → `bubbles holding set {ticker} --state ... --decision D-... --stop-loss ... --target ... --review-date ...`（或飞书 `/holding 修改`）
4. 持仓汇总 → `holding/持仓汇总.md` 更新价格与待拍板清单；飞书推送摘要
**沙盒模式**（policy sandbox.mode=true）：buy/add/sell 额外标注【沙盒】，只落库不推真仓，连续 2 次月度纪律 A 级后才退出沙盒。

## 角色分工（pi agent 定义，`invest-system/agents/`）

| 角色 | agent | 职责 | 模型档位 |
|---|---|---|---|
| 侦察员 | `invest-scout` | 数据快照/候选初筛/证据搜集（不做判断） | flash |
| 投研评审官 | `invest-analyst` | Step 0–7 主流程（假设-验证-决策） | pro（旗舰） |
| 空头复核官 | `invest-bear` | **独立上下文**证伪（自行取证≥3条新源） | **优先异构模型家族**（见 agent 内注释） |
| 风控官 | `invest-risk` | policy 硬规则 + 就绪度门审计，可否决 | flash |
| 复盘官 | `invest-reviewer` | 事后审计：假设兑现 + 纪律评分 + 归因 | flash |
| 组合经理 | **Paulus（人）** | 飞书决策卡片拍板 | — |

⚠ **模型异构**：analyst/bear 同模型时对抗是表演性的（共享盲区）——bear 尽量换不同模型家族。

工作流编排见 `investment/.pi/prompts/持仓决策.md`（pi 内 `/持仓决策` 一键跑全流程）。
**多空分歧处理**：bear 反对而 analyst 坚持 → 降级为保持/观察或标【分歧】交人裁决，禁止静默采纳任一方。

## 硬规则（引用）
- 所有事实带来源 + 时间戳，无依据不下结论；宏观数据必须实时验证不得用记忆（CLAUDE.md 约束 2/2b/2c）
- 单票 ≤20%、单行业 ≤30%、现金 ≥30%、持仓数 ≤8、同标的建仓间隔 ≥30 天、买入后 30 天强制复核（policy.yaml）
- 系统只出建议，**不自动交易**；拍板人 Paulus
