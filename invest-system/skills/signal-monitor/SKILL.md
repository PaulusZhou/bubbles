# 投资资讯与事件信号监测

## 概述

信息入口的唯一汇聚点：RSS 资讯 + 重大事件 + 会议解读三合一。**消费原则：只输出能推动决策的信号**——影响持仓驱动因子 → 触发持仓决策流程；蕴含产业链候选线索 → 喂给新股决策流程；其余只留档。

## 工作流程

### Step 1 · RSS 聚合（脚本）
```bash
python3 scripts/fetch_rss.py     # 抓取（源配置：scripts/rss_sources.json，15 个源）
python3 scripts/analyze.py       # 关键词过滤 + 分类 + 排序
```
产出摘要 → `{INVEST_ROOT}/rss-digest/digest_YYYY-MM-DD.md`。

### Step 2 · 事件检测与分级

| 类型 | 内容 |
|------|------|
| 行业大会 | 峰会、论坛、发布会、头部企业年会 |
| 国家会议 | 两会、政治局会议、经济工作会议、部委会议 |
| 政策变化 | 法律法规、产业规划、补贴、监管 |
| 国际事件 | 地缘冲突、贸易摩擦、汇率、美联储 |

**分级规则**（对投资的冲击度）：
- 🔴 **重大**：直接影响持仓假设的驱动因子或证伪条件（如产能政策突变、核心客户流失）→ **立即推送 + 触发持仓决策流程**
- 🟡 **关注**：影响行业景气或估值中枢（如量产进度、降息预期变化）→ 进当日信号汇总
- 🟢 **例行**：常规动态 → 只留档

### Step 3 · 信号分发（决策接口）
每条 🟡 以上信号必须标注去向：
1. **影响哪只持仓的哪个驱动因子** → 写入该标的需求证据表，并触发 `holding-decision-review`
2. **蕴含哪个行业的候选线索**（新订单/新产品/新政策催生的公司）→ 提交给新股决策流程的候选生成步
3. **都不是** → 归档，不推送

### Step 4 · 会议/事件深读（🟡 以上的重要会议）
对政治局会议、经济工作会议、关税事件等做 PEST 深读，方法见 [references/pest.md](references/pest.md)。
产出 → `{INVEST_ROOT}/events/`。

## 硬规则
- 每条信号带**来源链接 + 发布日期**；宏观/政策数据必须实时检索验证，禁止凭记忆（截至 X 年 X 月 标注法）
- 信息来源优先级：官方渠道 > 权威媒体 > 社区论坛
- 同一事件多源冲突时，取权威源并标注分歧

## 输出路径
| 产物 | 路径 |
|---|---|
| RSS 摘要 | `investment/rss-digest/digest_YYYY-MM-DD.md` |
| 事件/信号日志 | `investment/events/YYYY-MM-DD.md` |
| 会议深读 | `investment/events/{事件名}-PEST-YYYY-MM-DD.md` |
